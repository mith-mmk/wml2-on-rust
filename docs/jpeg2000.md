# JPEG2000 decoder: current review scope

This branch adds a bounded, independent Rust lossless JPEG2000 decoder. It remains
an opt-in `jpeg2000` feature in WML2 0.0.35; production decoding never calls
OpenJPEG. OpenJPEG/Pillow is used only to encode test inputs and provide an
independent pixel oracle. Main and the stable `jpeg2000` branch are unchanged.
This is source-branch work, not a published 0.0.35 feature announcement.

## Supported profile

- Raw J2K or JP2 with enumerated Gray (17) or sRGB (16) colour.
- Unsigned Gray8 or three equal-size, non-subsampled RGB8 components; RCT off/on.
- Reversible 5/3, decomposition levels 0–5, LRCP, one quality layer, complete
  coding passes and coding style zero. Per-component QCC overrides are supported.
- Legal power-of-two code-block axes 4–1024, area at most 4096; coefficient
  precision 1–16. Image and tile axes are at most 1024, reference-grid ends at
  most 32768 and raster tile count at most 256. Image/tile grid starts can differ;
  clipped, odd and tiny boundary tiles are supported.
- Up to 18 nonempty, contiguous tile-parts per tile, sequential TPsot starting
  at zero. TNsot may be unknown (zero), correct, or mixed; all known totals must
  agree with the final count. Complete packets must end each part. Psot can be
  zero only in the final codestream tile-part, whose extent is bounded by EOC.

The terminal Psot rule follows [T.800 A.4.2/Table A.6](https://www.itu.int/rec/dologin_pub.asp?id=T-REC-T.800-200208-S%21%21PDF-E&lang=e&type=items).
The implementation uses declared lengths and independently checked packet ends;
it does not search for markers inside compressed packet bodies. JP2 box bytes
following the codestream do not extend a terminal tile-part.

Unsupported inputs return an error: irreversible 9/7, multiple layers or partial
passes, tile interleaving/nonraster order, tile-header coding overrides, explicit
precincts/SOP/EPH, other progressions, signed/high-depth/alpha/subsampled components,
ROI, ICC and palette colour. This is a useful lossless subset, not full T.800 support.

## API and resource limits

Existing `image_load`, callback decoding and `ImageBuffer` APIs produce ordinary
RGBA8 with alpha 255. Direct `jpeg2000::decode` applies the default guarded limits.
The regular dispatcher uses its existing caller-supplied scope. Metadata charges
accumulate across comments and JP2 boxes in both paths and the scope restores
when a call ends, including errors. `ImageFormat::Jpeg2000` and its magic detection
are both gated by the feature, preserving pre-existing downstream exhaustive
matches when the feature is disabled. Default features, other codec APIs,
production dependencies and package version remain unchanged.

Input, dimensions/pixels, frames, metadata and expanded-workspace limits are
checked before callbacks/allocations. Decoder workspace is conservatively charged
as `64 * width * height * components + 8192`, plus the peak joined payload of any
multipart tile. Width/height are the actual cropped image. Single-part payloads
remain borrowed. Hard geometry, part-count and checked arithmetic bounds apply
alongside the configurable budgets. Unsupported or malformed framing rejects
before output initialization. This does not promise recovery from process-wide
allocator exhaustion.

The container, framing, packet/coefficient assembly, inverse transform and RCT
pipeline lives in `src/jpeg2000.rs`; the unchanged independent Tier-1 arithmetic
and bit-plane decoder lives in `src/jpeg2000_tier1.rs`. Packet boundary checks and
container parsing are kept separate so header changes cannot silently relax the
entropy decoder's bounds.

## PR readiness criteria and current evidence

The selected PR scope is ready when the supported/unsupported contract is explicit,
API/default-codec compatibility is preserved, fixed/random pixels match the
source (oracle encoder mismatches are separate), malformed inputs and exact/short
budgets behave correctly, ordinary workspace and actual WASM runs pass, images
are displayed, paired performance shows no material regression, the source
package is reasonable and independent actionable findings are resolved.

At the implementation checkpoint: ordinary release workspace passed 368 tests
with zero failures and 12 existing ignored tests across 43 targets. Minimal
feature-off passed 15 tests. Clippy reports 11 existing warnings outside the
JPEG2000 changes. Independent review reproduced and closed both P2 findings:
direct API cumulative metadata limits and feature-off exhaustive enum matching.
A separate robustness pass exercised 10,800 deterministic mutations with zero
panic and zero errors after initialization; its source snapshot preceded the
terminal-Psot addition. New terminal fixtures add 54 source-exact encodings and
18 negative inputs. Final WASM, display and paired cumulative Gray performance
are pending the final validation checkpoint; results will be appended here.

The new JPEG2000 oracle corpus and its integration test are retained in Git but
excluded from the crate archive. Cargo verifies the archive from unpacked sources;
the measured compressed package is about 428 KiB (previously 31 MiB). This keeps
large development-only oracle data out of the published artifact; publishing is
not part of this task. See [Cargo publishing guidance](https://doc.rust-lang.org/cargo/reference/publishing.html).
Historical stage reports below retain their original boundaries and measurements;
this document describes the current scope and supersedes their support summaries.

## Reproduction

```sh
cargo test --workspace --release --features wml2/jpeg2000
cargo test -p wml2 --release --no-default-features
cargo clippy -p wml2 --release --no-default-features --features jpeg2000 --tests
cargo build -p wml2 --release --no-default-features --features jpeg2000 --example jpeg2000_verify
python3 wml2/tests/fixtures/review/check_jpeg2000_terminal_parts_random.py /absolute/path/to/jpeg2000_verify --cases 24
python3 wml2-test/scripts/verify_jpeg2000_wasm.py
python3 wml2-test/scripts/verify_jpeg2000_wasm.py --default-features
cargo package -p wml2 --allow-dirty --no-default-features --features jpeg2000
```

Fixture generators require Pillow with JPEG2000/PLT support. The WASM verifier
requires an installed `wasm32-unknown-unknown` Rust target and Node.js, and runs
actual modules with no host imports. Temporary work directories start `.test*`.
Native pixel export can use `jpeg2000_verify INPUT OUTPUT.ppm --export-only`;
positive integer arguments retain timed decoding with 100 warmup calls.
