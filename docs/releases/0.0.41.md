# WML2 0.0.41

## Changes
- Add bounded image-information queries without pixel expansion through
  `wml2::image_info`, for enabled JPEG, PNG/APNG, GIF, TIFF/BigTIFF, PSD v1
  and JPEG XL parsers. Results distinguish coded, conditional output and
  intrinsic display geometry, and explicitly report unknown information.
  A successful query does not validate the remaining image or pixel stream.
- Add explicit half, quarter and eighth reduced-IDCT decoding for supported
  8-bit baseline Gray and three-component RGB/YCbCr JPEGs. The existing
  full-resolution decoder is unchanged; progressive, CMYK/YCCK and unsupported
  sampling/processes are rejected by the reduced route.
- Add static PNG EX encoding for Gray8/Gray16/RGBA8/RGBA16, and single-page,
  single-strip TIFF EX encoding for Gray16/RGBA16. TIFF supports none, standard
  MSB LZW and Deflate compression, horizontal prediction, Classic/BigTIFF and
  explicit little/big endian output. Both encoders preserve straight alpha and
  transparent RGB, remove row padding, apply the explicit normalized Exact/Round
  policy, validate output ICC declarations and preflight selected EXIF data.
- Add cooperative cancellation to the explicit JPEG XL sRGB display route with
  `image_from_srgb_with_limits_and_cancel` and typed `DecodeCancelled` errors.
  Cancelled private output is not returned. Recognized JPEG XL byte slices are
  borrowed so oversized inputs are rejected before an input-sized reader copy.
- Support bounded JPEG XL Brotli-compressed auxiliary metadata, retaining exact
  compressed source payloads separately from decompressed bytes. Add bounded
  common EXIF and UTF-8 XMP packet extraction. Original indexed source metadata
  is retained; common EXIF orientation is normalized to 1 because the JXL
  codestream orientation has already been applied to pixels.
- Decode supported JPEG XL main still images while safely skipping bounded
  embedded previews. Preserve separately declared intrinsic display dimensions
  on oriented axes without resampling the pixel canvas. Header-only queries
  can obtain this geometry without decoding ICC profiles or pixels.
- Accept one full-resolution straight integer JXL alpha channel with a depth
  independent of colour, each in 8/9/10/12/16 bits. Mixed-depth input uses a
  normalized native RGBA16 layout, retaining separate source colour/alpha depths
  and the existing explicit precision-conversion policy.
- Fix AVIF encoder capability reporting: builds with `avifenc` now report the
  existing AVIF save path consistently with their advertised extension.
- Retain combined regression coverage for geometry, metadata, mixed-depth alpha,
  cancellation and borrowed input admission, including independent pixel
  references and feature-aware WASM checks. These direct integration commits
  preserve the contracts of the twelve merged implementation PRs.

## Compatibility
- Existing default features, Rust 1.91 minimum version and submodule pins are
  unchanged. The JPEG XL runtime remains pinned to `jxl =0.7.4`; enabling
  `jpeg-xl` now also selects pure-Rust `brotli-decompressor =6.2.0` and
  `roxmltree =0.21.2`, with their default features disabled. PNG/TIFF independent
  decoders are development dependencies, not new runtime codec backends.
- Legacy PNG/APNG and 8-bit/multipage TIFF encoding remain on their existing
  APIs. EX output requires explicit format/precision choices and does not apply
  a CMS transform or silently promote source ICC metadata to an output profile.
  Known incompatible ICC models require an explicit compatible declaration or
  native Gray output. Exact conversion can reject normalized 12-to-16 scaling.
- Fixed JXL input, pixel, internal-layer, metadata and workspace caps remain
  enforced, including with caller `unlimited()`. Known-buffer admission and
  allocator-request limits are not guarantees about total process RSS.
  Cancellation is cooperative: individual codec tasks, serial work, allocation,
  container preflight and ICC parsing/transform compilation are non-interruptible;
  there is no cancellation-latency bound.
- Intrinsic size is display metadata, not a resize request; a skipped embedded
  preview is never substituted for the main image or exposed as a preview API.
  Header-only geometry success does not imply full decoding support.
- JXL animation, float/HDR rendering or tone mapping, a resumable/provisional
  output API, associated/subsampled alpha, general extra channels, original-JPEG
  bitstream reconstruction, JXL encoding and a `jxl` 0.8 migration remain outside
  the shipping contract. The separate evaluation PRs are not included here.
- Known TIFF compatibility gaps remain: `smallliz.tif` still encounters an
  old-style-JPEG scan-marker refusal with `tiff-jpeg` enabled, and `XING_T24.tiff`
  with missing strip byte counts is still rejected. The TIFF EX encoder does
  not claim to repair these existing decoder cases.
- This is a pre-1.0 release: Cargo treats 0.0.41 as a separate compatibility
  interval from 0.0.40. Pin the intended version when adopting it downstream.

## Validation
- The merged feature baseline
  [`8033d15d11b7c3de89ba2e753475050d0c37c69e`](https://github.com/mith-mmk/wml2-on-rust/commit/8033d15d11b7c3de89ba2e753475050d0c37c69e)
  passed [full main CI](https://github.com/mith-mmk/wml2-on-rust/actions/runs/41179054120):
  59 successful jobs and the expected codec-smoke skip.
- NERO verification of that feature tree passed twelve local test profiles.
  Across 134 selected JXL/JPEG/PNG/TIFF/AVIF files, 496 decode, information and
  scaled-query executions matched the independently checked composition.
  The 342 decode-route comparisons retained 170 successes and 172 expected or
  existing refusals; this is not a claim that every corpus input is supported.
  Representative independent libjxl comparisons and ten PNG/TIFF RGBA16 save
  round trips also passed. Original sample files were not modified.
- Release preparation validates the versioned notes and actual Cargo package,
  including the root README and normalized manifest. The tag workflow runs
  full checks at the tagged commit and builds example archives on Linux,
  Windows and macOS before GitHub Release creation. A successful feature-baseline
  run is not a substitute for those release-tag checks.
- The GitHub workflow does not publish to crates.io. Crates.io publication and
  downstream Viewer adoption are separate operations.
