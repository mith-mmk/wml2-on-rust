# WML2 0.0.47

## Changes

- Add typed, per-output color-processing observations through the public `color_outcome` API and versioned records in existing metadata values. Applications can distinguish applied ICC conversion, device-CMYK approximation and unreported states without parsing warning text.
- Report actual processing for supported JPEG/TIFF/PSD CMYK paths and JPEG XL still/callback-animation output, keeping source, reconstruction and output profile roles separate. TIFF pages and animation/layer outputs retain their own indexed observations.
- Preserve unknown status for uninstrumented paths, failed pages and malformed or future metadata records. A record is not a standalone decode-completion certificate; callers must discard it with pixels on failure or cancellation.
- Reconcile open issues with released JPEG XL support and remaining work, and restore the missing 0.0.45 links in both README histories.

## Compatibility

- Existing `DataMap` variants, buffer layouts, callback signatures and pixel-conversion algorithms are unchanged. The new typed enums are non-exhaustive, and missing records read as unknown rather than not applied.
- Added metadata keys and record bytes consume metadata budgets; JPEG XL includes them in pre-publication workspace accounting. Very tight caller limits can therefore reject an input that previously fit.
- Coverage is deliberately bounded. Other codecs, TIFF native Gray/RGB EX and native JPEG XL animation results are not universally instrumented. This release does not implement new color transforms, HDR support or JPEG XL encoding.
- Cargo treats 0.0.47 as a separate compatibility interval from 0.0.46. Downstream applications must update their requirement explicitly. Features, dependencies and Rust 1.91 minimum support are unchanged.
