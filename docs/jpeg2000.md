# JPEG2000 decoder: current source profile

The non-default `jpeg2000` feature uses WML2's independent Rust decoder.
Production decoding has no OpenJPEG, OpenJPH, FFmpeg or native decoder dependency.
The expanded profile described here is unreleased source work on top of the
JP2 compatibility follow-up; the package version remains 0.0.35.

## Supported profile

- Raw J2K and JP2; signed or unsigned 1–8bit samples, normalized to RGBA8.
  Gray, RGB, Gray/alpha and RGB/alpha are supported. Subsampled components are
  assembled on their native grids before nearest-neighbour expansion to the
  reference grid, including odd origins and sampling across tile boundaries.
- JP2 enumerated sRGB (16), Gray (17) and sYCC (18), BPCC, bounded palettes,
  direct/palette CMAP and CDEF colour order and global straight/premultiplied
  alpha. Palettes support 1–8bit columns. Premultiplied colour is unpremultiplied
  for the ordinary straight-alpha RGBA output. Low-depth colour and alpha use
  the full 0–255 output range.
- Reversible 5/3 or irreversible 9/7, scalar derived/expounded quantization,
  RCT/ICT, component COD/COC and QCD/QCC overrides, maxshift ROI and partial
  coding passes. Up to 32 decomposition levels, subject to coefficient and
  resource bounds. Code-block axes are powers of two from 4 through 1024 and
  their area is at most 4096; reconstruction precision is bounded to 28 bits.
- Multiple quality layers; LRCP, RLCP, RPCL, PCRL and CPRL, POC, multiple
  precincts and precinct-clipped code blocks. Classic Tier-1 supports BYPASS,
  RESET, TERMALL, VSC, PTERM and SEGSYM coding styles.
- CAP-declared HTJ2K HTONLY cleanup, significance propagation and magnitude
  refinement, including skipped sets. HTMIXED block dispatch is not supported.
- Interleaved or reordered tiles, sequential parts within each tile, zero,
  known or mixed TNsot totals, empty parts, terminal Psot=0, packed PPM/PPT
  headers, PLT/TLM checks and SOP/EPH. At most 65535 tiles and 255 parts per
  tile. Complete packets must end each part; all declared tiles and quality
  layer packets must be present.
- Part 1 Rsiz 0/1/2 and the supported HT capability 0x4000. Reference-grid
  coordinates use the declared unsigned 32-bit geometry; cropped image size
  remains constrained by the configured pixel/workspace limits.

JP2 accepts extended box lengths and bounded ancillary boxes. Resolution boxes
are validated without rescaling pixels. The first understood colour declaration
is used; later colour declarations are ignored. ICC methods 2/3 and sample or
palette depth above 8 remain deferred. Arbitrary multicomponent data without a
display mapping, per-colour alpha associations, other extended capabilities and
HTMIXED return explicit errors. This is not a claim of complete T.800/T.814
conformance. No missing-tile or missing-quality-layer recovery is performed.

The framing/container rules follow [T.800, including Annexes A and I](https://www.itu.int/rec/dologin_pub.asp?id=T-REC-T.800-200208-S%21%21PDF-E&lang=e&type=items).
HT decoding and lookup tables follow [T.814 (06/2019), clauses 7/B and Annex C](https://www.itu.int/rec/dologin_pub.asp?id=T-REC-T.814-201906-I%21%21PDF-E&lang=e&type=items).
The HT table source PDF digest is recorded in `src/jpeg2000_ht_tables.rs`.

## API and resource limits

Existing `image_load`, callback and `ImageBuffer` APIs return ordinary RGBA8,
including alpha where supplied. Direct `jpeg2000::decode` uses default guarded
limits; dispatch honours the caller's `DecodeLimits`. No public API, default
features or production dependencies change. Feature-off enum/magic detection
retains the pre-existing behaviour.

The established small-profile path runs first. Only an `UnsupportedFeature`
error retries with the general assembler; malformed input and exhausted budgets
cannot bypass limits through this fallback. Failed attempts restore their
metadata charges before retrying. Decoding and validation complete before output
initialization, so rejected input cannot leave partially emitted image pixels.

The established path retains its conservative workspace formula and exact
budget tests. The general path checks RGBA output, native component storage,
tile coefficient/reconstruction workspace, block state and packet/progression
directories. Input, pixels, frames and cumulative metadata limits also apply.
Checked arithmetic, fallible major allocations and coefficient bounds supplement
those limits; process-wide allocator exhaustion is not recoverable by contract.

`src/jpeg2000_general.rs` owns the expanded container, packet and component-grid
assembly. `src/jpeg2000_tier1.rs` implements classic MQ/RAW passes and segment
state; `src/jpeg2000_ht.rs` and `src/jpeg2000_ht_tables.rs` implement HT blocks.
The established container/fast path and reversible synthesis remain in
`src/jpeg2000.rs`; scalar dequantization, floating 9/7 and ICT are reused from
`src/jpeg2000_irreversible.rs`.

## QCC precedence follow-up (2026-10-15)

Tile-header QCC previously lost its component override when a QCD followed it.
The main and tile headers now share default-before-component application order,
as required by T.800 A.3/A.6.5. Header marker order therefore does not change the
decoded pixels. Later tile-parts still cannot introduce coding overrides.

Twenty-four regressions permute QCD and two component QCCs in raw/JP2, with
single/multiple tile-parts. They use the independently decoded canonical-order
image as their reference: the Pillow/OpenJPEG build used here also exhibits the
reverse-order issue, so its reverse-order output is not the oracle. The new
regression fails before the fix. After the fix all 24 outputs are byte-identical
to one another and differ from the canonical independent oracle by at most one
channel value (previously up to 53).

Native workspace tests pass 380 with 12 existing ignored; JPEG2000-only tests
pass 48. Actual minimal/default WASM each pass 72 pixel/API/limit cases, including
the 24 new permutations. Rust 1.91, Clippy with style warnings, formatting,
unpacked source-package verification, displayed pixel comparisons and six paired
Windows performance cases also pass. Timing changes range -1.085% to +2.498%
on this host, with identical output hashes for equivalent supported inputs.
The 90 non-book external inputs were rechecked: 65 convert and 25 reject,
with all 65 successful PNGs byte-identical to the preceding run. The prior
24-book-page evidence is retained without repeating that run for this fix.
[QCC validation](jpeg2000-qcc-order-validation.json) records this follow-up's
source hashes and supersedes the earlier expanded snapshot for changed sources.

Regenerate its fixtures with
`python3 wml2/tests/fixtures/review/generate_jpeg2000_qcc_order.py`.

## Expanded-profile validation (2026-10-15, d88eb08 snapshot)

The external converter corpus contains 114 inputs. Conversion improved from
14 successes / 100 errors to **89 successes / 25 errors**, including all 24
large book-page JP2 images. The 25 remaining inputs comprise 21 deferred
high-depth/ICC inputs (one has both) and four exceptional inputs:

| Input | Reason |
| --- | --- |
| `openjpeg_Marrin.jp2` | Only 12 of 24 declared quality-layer packets are present. Pillow renders its available layer; its one-layer and all-layer outputs are identical. WML2 rejects the missing packet inventory. |
| `openjpeg_conformance_b2_mono.j2c` | Incomplete declared tile directory; Pillow also fails. |
| `pillow_00r1_graya_la.jp2` | Packet data exceeds the declared inventory; Pillow also fails. |
| `openjpeg_conformance_p0_13.j2k` | 257 components with no display mapping. Ordinary RGBA cannot preserve all components. |

Pillow, FFmpeg and ImageMagick reject the 257-component input; OpenJPEG's PGX
writer exports each component as a separate file. WML2 reports the missing
display mapping instead of silently dropping components. Per-component export
is not part of the ordinary converter API.

Independent pixel checks use Pillow/OpenJPEG, upstream OpenJPEG-data PPM/PGM/PGX
and ImageMagick. Most outputs differ by at most one channel value; the two sYCC
rounding cases differ by at most 2/3. The large book images and irreversible HT
sample differ by at most one; the reversible HT sample is exact. Raw low-depth,
odd-origin and subsampled component comparisons apply explicit sample-depth
normalization and reference-grid sampling. Upstream component/reference images
resolve cases where Pillow's rendered image is incorrect or rejects valid raw
component layouts. These comparisons and each output hash are recorded in
[expanded validation](jpeg2000-general-validation.json).

New deterministic fixtures cover both filters, five progression orders, multiple
layers/precincts, alpha and six decomposition levels. Two hand-assembled normative
HT examples are independently decoded by OpenJPEG; a third moves the level-zero
block to the unsigned 32-bit coordinate boundary. Previously unsupported valid
fixtures now have positive independent pixel assertions. Native workspace tests
pass 379 with 12 existing ignored; feature-off tests pass 37. Each actual
minimal/default WASM build passes 1,796 established cases and 140 rejections;
the final expanded-profile builds each pass 48 pixel/API/limit cases. The
established runtime runs preceded the final general-path allocation guards;
both 48-case runtime builds verify all final production source hashes. Resource
and callback guards, the verified 454 KiB source package, image display and paired
Windows performance are recorded in the validation file.
External sample binaries are not redistributed in the source repository/package.

The paired established-path benchmark uses eight alternating pairs on four
inputs with fixed CPU affinity. Output hashes are identical; median changes on
this Windows host range from -1.536% to +0.544%. This does not establish speed
on other hosts or compare newly supported inputs that the baseline rejects.

Reproduce the added runtime coverage with:

```sh

python3 wml2/tests/fixtures/review/generate_jpeg2000_general.py

python3 wml2-test/scripts/verify_jpeg2000_general_wasm.py --default-features --work-dir .test-general-wasm-default
```

Fixture regeneration requires Pillow/OpenJPEG. Runtime verification requires
the installed `wasm32-unknown-unknown` target and Node.js. Source/oracle fixtures
are retained in Git and excluded from the published crate archive.

Fixture generators require Pillow with JPEG2000/PLT support. The WASM verifier
requires an installed `wasm32-unknown-unknown` Rust target and Node.js, and runs
actual modules with no host imports. Temporary work directories start `.test*`.

positive integer arguments retain timed decoding with 100 warmup calls.
