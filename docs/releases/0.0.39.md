# WML2 0.0.39

## Changes
- Fix JPEG files failing before pixel decoding because an EXIF metadata
  sub-IFD's omitted next-pointer slot overlaps an explicitly referenced tag
  value. Interpret offsets relative to the bounded TIFF payload and do not
  interpret those value bytes as another IFD link. Regular TIFF image parsing
  remains strict.
- Continue JPEG pixel decoding when bounded optional EXIF metadata is malformed
  or unsupported. Callback decode APIs report `InvalidExif`; raw APP1 bytes
  remain available as `EXIF Raw`. Valid EXIF and Orientation 1 through 8 are
  retained. JPEG structure/coding errors, cancellation, allocation failures and
  resource limits still fail the decode.
- Use published `avif-rust` and `avifenc-rust` 0.1.2 dependencies. Preserve the
  existing adapters, feature gates and explicit precision/color contracts.
- Select relevant optional-codec CI for recognized isolated changes, avoid
  duplicate feature-branch push/PR runs, and prepare FFmpeg only in AVIF rows
  that need it. Main/manual/tag verification remains full.

## Compatibility
- Default features and encoded-coordinate pixel output remain unchanged.
  Applications such as Viewer continue to apply retained Orientation themselves.
- `JpegAppHeaders` and `JpegWarningKind` gain `InvalidExif` variants; callers
  exhaustively matching these public enums must handle the new variants.
- Malformed optional EXIF can now produce a warning plus pixels instead of a
  fatal image error. Convenience APIs that omit warnings still retain raw EXIF
  metadata. Aggregate metadata limits continue to include retained/parsed data.
- This is a pre-1.0 release: Cargo treats 0.0.39 as a separate compatibility
  interval from 0.0.38. Pin the intended version when adopting it downstream.

## Validation
- Synthetic EXIF/JPEG regression coverage includes both byte orders, overlapping
  metadata/value layouts, retained Orientation 1 through 8, unchanged pixel
  output, malformed signatures/headers, cycles, nested pointers, out-of-bounds
  data, resource limits and fatal JPEG structural errors.
- Local private-file verification exercised the Viewer 0.0.24 built-in core and
  file/byte Canvas paths against the fixed implementation, with exact RGBA
  agreement and no plugin fallback. Five Viewer orientation tests, covering all
  eight orientations, passed. This was a headless integration check, not an
  observation of the GUI. No private input or personal log is distributed.
- See [JPEG EXIF behavior](../jpeg-exif.md) and the
  [AVIF dependency validation](../avif-registry-012.md) for scope and commands.
- The tag workflow runs the shared full checks and validates version/tag/SHA
  alignment before creating the GitHub Release and example archives. Registry
  package verification/publication is a separate release step.
