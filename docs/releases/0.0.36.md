# WML2 0.0.36

## Changes
- Add an opt-in, independent Pure Rust JPEG2000 decoder for raw J2K and JP2
  through the `jpeg2000` feature. Production decoding has no OpenJPEG, OpenJPH
  or FFmpeg dependency; there is no JPEG2000 encoder in this release.
- Decode signed/unsigned 1–8bit Gray/RGB samples, alpha, subsampled components,
  palette/CMAP/CDEF layouts and enumerated sYCC to ordinary RGBA8. Native
  component grids are assembled before reference-grid upsampling.
- Support reversible 5/3 and irreversible 9/7, RCT/ICT, multiple quality layers,
  all five Part 1 progression orders, POC, multiple precincts, maxshift ROI,
  component coding/quantization overrides and classic MQ/RAW coding styles.
  Add independently implemented HTJ2K HTONLY block decoding.
- Accept bounded JP2 extended box lengths, ancillary metadata, resolution
  metadata, legal header flags and the first understood colour specification.
  Support reordered/interleaved tiles, multiple tile-parts, terminal Psot=0,
  packed PPM/PPT headers, PLT/TLM checks and SOP/EPH.
- Fix tile QCC precedence so a later QCD cannot erase a component override.
  Add 24 marker-order regressions covering two component overrides, raw/JP2
  and single/multiple tile-parts.
- Add JPEG2000 feature/platform CI coverage and retain independent source/oracle
  fixtures in Git while excluding the large development corpus from the crate.
  Update the English and Japanese README examples and supported profile.

## Compatibility
- `jpeg2000` is not enabled by default. Opt in with
  `wml2 = { version = "0.0.36", features = ["jpeg2000"] }`.
  Enabling it adds `ImageFormat::Jpeg2000`; downstream exhaustive enum matches
  may need an additional arm. Feature-off detection and enum variants remain
  unchanged. Existing image/callback APIs return RGBA8, including supplied alpha.
- Default features, existing codec APIs, production dependency versions and
  Rust 1.91 minimum support are unchanged from 0.0.35.
- JPEG2000 sample/palette depths above 8 and ICC remain deferred. HTMIXED,
  per-colour alpha associations and unmapped arbitrary component layouts are
  unsupported. Missing declared tiles/quality-layer packets reject instead of
  silently recovering or discarding components. This is a bounded supported
  profile, not complete T.800/T.814 conformance.
- Input, pixel, frame, metadata and workspace limits apply before image output.
  See the [supported profile and limits](../jpeg2000.md) for the exact scope.

## Validation
- Native workspace: 380 passed with 12 existing ignored tests; JPEG2000-only:
  48 passed. Actual minimal/default WASM each pass 72 pixel/API/limit cases.
- The 114-input external converter corpus improves from 9 successes before
  the container fixes to 14, then 89 with the expanded decoder, including all
  24 large book pages. The remaining 25 inputs include 21 deferred high-depth/ICC
  cases and four incomplete/excess-packet or unmapped-component cases.
- The QCC regression reduces maximum channel error from 53 to 1 against the
  canonical independent oracle; all 24 equivalent header orders produce
  identical pixels. Rechecked 90 non-book inputs retain their previous statuses
  and all 65 successful PNG hashes.
- Independent pixel checks, image display, resource/callback guards, Rust 1.91,
  actual WASM and paired Windows benchmarks are recorded in the
  [QCC follow-up](../jpeg2000-qcc-order-validation.json) and
  [expanded-profile validation](../jpeg2000-general-validation.json).
  The six follow-up performance cases range from -1.085% to +2.498% on one host;
  these measurements are not a cross-host performance guarantee.
