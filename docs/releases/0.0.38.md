# WML2 0.0.38

## Changes
- Retain bounded source ICC provenance across JPEG, PNG, BMP V5, GIF, TIFF,
  PSD and JP2. Declare an active output profile only when it applies to the
  returned samples. Keep TIFF palette profiles and per-display-page identity
  consistent; discard malformed JPEG ICC APP2 associations within aggregate
  limits while continuing image decoding.
- Add `DrawCallback::begin_image` with a default implementation. Built-in
  buffers reset metadata and stale EX storage between images; nested decoding
  preserves the outer image lifecycle and callback cancellation/error behavior.
- Correct AVIF still ICC priority and encoded matrix/range reconstruction.
  Restore Gray alpha by plane identity in the ICC/EX reconstruction path,
  validate the actual selected `prem`
  target, unassociate before nonlinear conversion, apply the own ICC engine
  once, then quantize ordinary display output. Native/EX samples retain their
  source-coordinate contracts and source profiles.
- Update the optional own `icc-profile` dependency from 0.0.6 to 0.0.7.
  Add checked native Gray/RGB output layouts across U8/U16/F32, preserving alpha
  and provenance, with an optional output sample-buffer cap. Exact adjacent
  colour reuse reduces repeated transform work without approximating pixels.
- Add non-default `jpeg-xl`, using published `jxl = 0.7.4` with its defaults
  disabled. Support the documented bounded integer still profile, bare and
  `jxlc`/ordered `jxlp` containers, orientations, native EX precision and an
  explicit own-engine sRGB display API. Coded 9/10-bit samples normalize to
  16-bit storage while retaining coded-depth metadata.
- Admit supported cropped/reference/blended JXL internal layers with bounded
  header/TOC/ICC preflight. The official `sunset_logo` now displays at 924×1386;
  internal 2048×1024 layers with negative origins remain checked independently
  of the final canvas. Preserve uncompressed opaque source boxes such as `jbrd`.
- Fix the optional Shift-JIS dependency declaration. Keep fixture-dependent
  JP2 contributor tests outside the published package, consistently with the
  excluded large JP2 oracle corpus.

## Compatibility
- Default features remain unchanged. JPEG XL requires explicit `jpeg-xl`;
  `image-buffer-ex` and `color-management` remain opt-in. The default example
  ZIP builds do not enable JXL. This is a pre-1.0 release: Cargo treats 0.0.38
  as a separate compatibility interval from 0.0.37.
- Public ICC re-exports (`RenderingIntent`, `TransformOptions`) and CMS error
  types now originate from `icc-profile 0.0.7`. Applications exchanging those
  types directly must align dependency versions or use WML2's re-exports;
  standalone 0.0.6 types are not interchangeable.
- Existing callback implementations inherit the default `begin_image` method.
  Reusing custom forwarding wrappers should forward the lifecycle reset;
  downstream traits with the same method name may need explicit qualification.
  Enabling JXL adds `ImageFormat::JpegXl`, so exhaustive matches may need a case.
- Source/output ICC metadata and corrected TIFF/AVIF pixels intentionally
  change in affected cases. Inapplicable source profiles remain provenance,
  rather than being falsely declared as output profiles. Invalid declarations,
  incompatible device models and resource-limit failures can reject earlier.
- JP2 method2 Gray/RGB ICC retention does not claim JPX, unrestricted method3,
  or implicit colour conversion of every native/reduced output. General CMYK,
  4D-CLUT and arbitrary N-colour CMS remain outside the supported scope.
- Managed AVIS and broader AVIF geometry/transfer cases remain deferred.
  JXL float/HDR/tone mapping, animation/previews, associated or mixed-depth/
  subsampled alpha, `brob` decompression, JPEG bitstream reconstruction,
  encoding, SIMD and threading extensions remain unsupported. Accepting `jxll`
  levels does not claim the entire Level10 profile.
- Logical workspace estimates and selected allocator measurements are not a
  process-RSS guarantee. JXL keeps fixed dimension/pixel limits, at most
  64 internal layers and 4096 TOC entries, plus canvas/frame/metadata/workspace
  quotas and the pinned codec's runtime sample limit.

## Performance
- Exact repeated-colour reuse materially reduces the measured AVIF ICC cost
  on flat/run inputs. A varying-colour 128×128 control still costs about
  9.78× its equivalent no-ICC path; general inverse-TRC cost remains. Neither
  path ignores ICC nor reduces transform precision. Small measured deltas
  retain their noise and no universal no-regression guarantee is claimed.
- JXL's additional layer preflight costs about +5 µs / +7.7% on the measured
  small ICC-bearing EX case; managed output measured about +3.5%. The new
  layered workload has no successful old baseline. These cloud measurements
  are not Windows-local performance or memory claims.
- See the [AVIF measurements](https://github.com/mith-mmk/wml2-on-rust/blob/v0.0.38/docs/avif-icc-performance.md) and
  [JXL layer validation](https://github.com/mith-mmk/wml2-on-rust/blob/v0.0.38/docs/jpeg-xl-layers.md) for controls, limits and methods.

- Update the library version, tracked lock, dependency examples, current JXL
  guide and both README histories to 0.0.38. The unpublished `wml2-test` package
  remains 0.1.0.
- Include the focused AVIF ICC/Gray-alpha regressions in the existing Windows
  and macOS platform jobs, alongside the required release feature matrix.
- Independent PR reviews identified the Gray-alpha, selected-alpha and
  packaged-JP2-test corrections above. Targeted tests, independent pixel/CMS
  references, actual image display and paired benchmarks cover those fixes.
  Historical validation checkpoints remain in the linked reports; counts
  overlap and are not summed into a repository-wide total.

  workflow gates GitHub Release creation on shared feature/platform CI,
  tag/SHA/version/body checks and example ZIP builds on Linux, Windows and macOS.
