# JPEG XL entropy budget evaluation

This is an **evaluation patch**, based on draft [#73](https://github.com/mith-mmk/wml2-on-rust/pull/73) (`8fa0b978c4f68e998439e1bffe0b567f46024074`). WML2 still depends on the unchanged published `jxl =0.7.4`. Nothing here activates a budget in WML2's product decoder or completes [#37](https://github.com/mith-mmk/wml2-on-rust/issues/37) / [#63](https://github.com/mith-mmk/wml2-on-rust/pull/63). No fixed cap changes, larger-image admission, merge, upstream submission or dependency release accompanies this stage.

## Reproduce

Use Rust/Cargo 1.91, Python 3.12 and optionally Node 24 plus `rustup target add wasm32-unknown-unknown`:

```sh
python -B wml2-test/scripts/evaluate_jpegxl_entropy_budget.py --output .test-entropy-eval --wasm --wml-regression
```

Use a fresh `.test*` output directory each time. `--offline` works with the locked registry packages already cached. `--target-dir /path/.test-target` optionally reuses build artifacts. The script locates the registry `.crate` archive (or runs `cargo fetch --locked`), verifies SHA-256 `43b041e4bd5bb931cf73b271bc3304eb135bb473914877d64bf77fdf5b4d4687`, extracts a scratch copy, checks source hashes, strictly applies [the six-file patch](../wml2-test/scripts/jxl_entropy_budget_074.patch), verifies resulting hashes, and builds an isolated consuming Cargo root. It never edits the product manifest or lock. An optional second consumer runs existing WML2 tests against the scratch dependency and verifies every registry package version against the product lock. The source is upstream commit `624ce908afcf8eb0dc2585a671535eaabb5d88cc`, crate subpath `jxl`; its [BSD license](../wml2-test/scripts/jxl_entropy_budget_LICENSE.txt) is retained.

The [Rust harness](../wml2-test/scripts/jxl_entropy_budget_eval.rs), [harness lock](../wml2-test/scripts/jxl_entropy_budget_eval.lock), [source/patch hashes and validation snapshot](jpeg-xl-entropy-budget-evaluation.json) are committed. CI executes the native fault tests and the six actual WASM groups. Logs/report remain in the chosen scratch directory.

## Implemented scope

`EntropyBudget` clones share an atomic live-reservation counter. `EntropyVec` admits requested payload capacity before fallible allocation. Its non-cloneable lease follows the retained map, releases after storage is freed, and rolls back on allocation/parse failure. Histograms retains its hot map as a private raw Vec with a separate lease; parsing transfers those owners only after all fallible histogram construction finishes. A dedicated resize helper preserves full overlap admission and storage-before-lease release. Budgeted resize reserves the full replacement while the old backing store remains charged; failure preserves the old data and reservation. Shrinking a Vec's length does not release retained backing capacity. Verification uses a fixed stack presence table instead of a heap HashSet over u8 values.

The explicit low-level `decode_context_map_with_budget` and `Histograms::decode_with_budget` pass the same budget through recursively decoded maps. A `SymbolReader` derived from those histograms automatically reserves its 2^20-element u32 LZ77 window (4 MiB). The window keeps the existing Vec and symbol loop; a separate move-only lease follows it. Readers may outlive the originating Histograms without losing the reservation. `check_final_state(self)` consumes/releases a reader; checkpoints copy fixed stack state and do not duplicate a heap window. Histogram context-map padding now returns a fallible Result, propagated by the frame caller. **This changes the low-level `Histograms::resize` return type and is a proposed dependency API change, not a drop-in published replacement.**

This ledger measures admitted **requested payload capacity**, including resize overlap. It does not measure allocator rounding, overhead, RSS or all codec storage. `Arc::new` budget setup itself remains infallible; test/setup allocations and the atomic counter's object storage are outside the payload quota. High-water values are peak reservations, including reservations whose physical allocation is subsequently refused.

## Validation and limits

Fourteen native tests cover exact/minus-one quotas; simple, complex and MTF maps; nested map/window overlap; singleton histograms; post-parse padding; malformed/truncated input; checked capacity overflow; moves and cloned budget handles; shared limits across eight threads; two simultaneous windows and third-window denial; reader checkpoints and ownership after histogram drop. Actual allocator null returns are injected for initial map, replacement resize and 4 MiB window requests, followed by successful retries. A deallocation observer verifies that old/new storage is freed before its corresponding reservation is released. Quota denial is verified before the allocator request. A frozen independent ICC fixture exercises WML2-style direct Histograms/SymbolReader preflight calls with an explicitly supplied budget, including a cloned BitReader and two live reader graphs.

Actual WASM runs six non-fault case groups with 32-bit usize and a 64 MiB linear-memory ceiling. It uses no imports and verifies rejection of a memory.grow request beyond that ceiling. Threading and allocator-null injection are native-only; no native i686 execution is claimed for this stage. The temporary WML2 consumer's 84 regression tests verify existing independent pixels/metadata, malformed inputs, refusal boundaries and cancellation with the modified codec's **unbudgeted** legacy path. These regressions do not prove that product decoding uses the new quota.

A displayed 606×500 CMS decode matches the independent frozen oracle within maximum RGB error 1, with exact alpha. The original evaluation patch's ordinary photo slowdown was reproduced and diagnosed with controlled builds, byte-identical A/A rebuilds, source ablations and untimed reservation counts. Keeping the histogram hot storage as a raw Vec with a separate lease removes that regression in the measured cases without relaxing admission or ownership. The [performance diagnosis](jpeg-xl-entropy-budget-performance.md) and [full measurement record](jpeg-xl-entropy-budget-performance.json) give matched settings, process counts, variability, intervals and limits. These results do not qualify every platform or connect a decoder-wide quota. The old cross-context measurements remain labeled historical in the validation snapshot.

## Required work before product integration

The default free context-map function and default Histograms decoder deliberately remain unbudgeted. No decoder option or BitReader field is added in this first stage. A BitReader clone carries bit state only: the low-level test supplies the same budget explicitly to each new histogram graph. Fresh readers, generated readers and callers cannot silently be declared covered.

- WML2's direct ICC preflight and IncrementalTocReader → Permutation → entropy calls still need an explicit propagation route. Only the direct ICC evaluation test is connected here; the production ICC and permuted TOC paths are unchanged.
- Decoder options, incremental SmallBuffer::with_br, LF/HF/group/section reader construction, patches/splines, coefficient order and modular tree creation need explicit propagation. Generated UnconditionalCoder paths must preserve that route. No jxl_macros patch is established as necessary by this evaluation.
- The separately retained BlockContextMap uses the legacy free function and is outside this first scope. ANS/Huffman tables and uint_configs are also outside it, even when the containing Histograms has a budgeted context map.
- Frame/modular planes, palette/transform/scratch storage, reference layers, section/TOC buffers, metadata/ICC expansion and CMS need their own lifetime accounting. Finite adapter estimates from #72/#73 remain conservative and separate. They must not be replaced with this partial ledger.

Distribution remains a separate decision. A root Cargo `[patch]` is suitable for this experiment but must be repeated by consumers; a path+version dependency falls back to the registry when published ([Cargo override rules](https://doc.rust-lang.org/cargo/reference/overriding-dependencies.html#working-with-an-unpublished-minor-version), [multiple locations](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#multiple-locations)). No external repository was created or written. A distributable dependency source/version, API compatibility policy and the missing propagation/allocation coverage must be agreed and validated before any product guarantee or cap change.
