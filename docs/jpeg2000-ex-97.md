This continuation starts at colour PR #15 head
`cff3f3672bc22e1ad0f3e1aa940ab0788f22c4d4` on the separate
`codex/jpeg2000-ex-irreversible-high-depth-20261017` branch at WML2 0.0.36.
The capability is included in [WML2 0.0.37](releases/0.0.37.md); the original

The colour PR independently passed both push and PR CI, 49 jobs each.

## Accepted profile

Enable `jpeg2000,image-buffer-ex`. The established unsigned uniform 12/16-bit,
full-resolution Gray, RGB and explicitly declared JP2 straight RGBA contracts
from the [reversible colour stage](jpeg2000-ex-color.md) also accept classic
irreversible 9/7, scalar-derived (QCD/QCC style 1) or scalar-expounded (style 2)
quantization, and optional RGB ICT. The new floating profile permits 0–6 DWT
levels. Components must use the same filter; existing coefficient precision,
packet completeness, geometry and resource limits still apply.

Gray declares Gray12/16 and packs two LE bytes per pixel. RGB declares RGBA12/16,
adds alpha 4095/65535 and packs eight bytes per pixel. RGBA still requires JP2 RGB
enum 16 and complete CDEF: colour components 0..2 bijectively associated with
1..3, followed by component 3 whole-image straight opacity (type 1, association
0). Colour order may be permuted. The alpha plane undergoes its own inverse
quantization and DWT, never ICT, and is not used to multiply RGB.

Inverse quantization uses component precision, retaining f64 samples through
9/7 and ICT. Final conversion checks finiteness, rounds the centred sample to
nearest even, adds the source-depth DC shift, clamps to 0..4095/65535 and writes
explicit LE bytes. There is no intermediate U8 normalization. Exact/Round
storage conversion remains explicit and includes alpha. Byte strides, padded
subrectangles, callbacks, Abort and error propagation retain their existing
contracts. Reconstruction and validation finish before callbacks.

The new workspace charge is 28 bytes per component tile pixel: retained i32
coefficients, f64 reconstructed plane and worst-case packed-column/inverse-line
scratch (4+8+8+8). Output canvas and packet/configuration storage are charged
separately. Reversible EX and legacy allocation paths retain their prior charge.
This is a checked buffer budget, not an allocator/process RSS bound.

Signed/mixed precision, mixed filters and other coded depths,
subsampling, palette/CMAP, HT, ROI, implicit/premultiplied/per-colour/nontrailing
alpha and raw four-component alpha remain unsupported. Existing reversible
Gray/RGB/RGBA and legacy 1–8-bit RGBA8 acceptance is preserved. No general colour
management, animation or streaming API is added.

## Numerical verification

The generator retains original U16 input separately from independent OpenJPEG
2.5.3 decoded PGX and packed references. There are **216 streams**: both depths,
Gray/RGB/RGBA, ICT on/off, raw/JP2, complete permuted CDEF, zero/max/low bits,
transparent RGB, odd sizes and origins, offset tiles, singleton edges, six
levels, RPCL layers/tile-parts, scalar-derived/expounded quantization and
rate-8 lossy controls. Every encoder and independent PGX decoder invocation
succeeded. The failed OpenJPEG 17×15 offset-tile encoder profile is excluded;
16×16 offset tiles are independently encoded and decoded instead.

Lossy output is **not** required to equal the original image. Each manifest
entry reports independent decoded-reference versus source max/mean/RMSE,
separately from WML2 versus decoded-reference errors. Derived-header controls
intentionally alter quantization mantissas; their independent decode, rather
than their unmodified source, is the oracle.

For this corpus, OpenJPEG decoder differences are capped at 1 source-domain
sample for 12-bit and 4 for 16-bit, with mean absolute caps 0.1 and 1.25.
These are regression bounds for these fixtures, not universal quality or
conformance guarantees. The 16-bit maximum is about 0.0061% of full scale.
OpenJPEG deliberately uses historical `two_invK = 1.625732422f` and compensates
non-LL quantization gains; this differs from the Table F.4 normalization used
here. See its [inverse DWT](https://github.com/uclouvain/openjpeg/blob/v2.5.3/src/lib/openjp2/dwt.c)
and [step-size compensation](https://github.com/uclouvain/openjpeg/blob/v2.5.3/src/lib/openjp2/tcd.c).
Production keeps the established f64 kernel and leaves legacy synthesis
unchanged.

A second independent reader, FFmpeg 7.1.5's native `jpeg2000` decoder (explicit
`-c:v jpeg2000`, not its libopenjpeg wrapper), reads 204 of these streams. WML2
and FFmpeg differ by at most **one** source-depth sample; the maximum per-image
mean is 0.00794. FFmpeg rejects the remaining 12 colour RPCL multiple-layer
component/tile-part streams at SOT; they are covered by successful OpenJPEG
PGX comparisons and are not counted as FFmpeg passes. All reference hashes,
per-case comparisons and failures are retained in the validation artifacts.

Exact stride/conversion/callback assertions use the actual decoded U16 canvas,
so numerical tolerance cannot hide storage-contract errors. Existing reversible
fixtures continue to require exact source/PGX equality. Four formerly rejected
9/7 fixtures now explicitly test successful high-depth declarations; remaining
signed/ROI/depth/alpha failures still precede callbacks. Invalid quantization,
excess levels/precision and mixed filter overrides are also checked.

## Display, performance and memory

The retained preview was visually checked: source, independent reconstruction,
WML2, amplified differences and alpha panels show readable colours, matching
tile placement and straight transparency. Lossy controls visibly differ from
the original as expected.

Eight alternating paired runs use identical Rust 1.91 release examples and flags,
CPU affinity, and immutable cff3f36 baseline binaries. Current builds use a
separate Cargo target directory; baseline feature rejection and binary hashes
are checked before timing. Every existing output hash is preserved. Gray EX
medians change -0.80%/-0.08%; reversible colour ranges -1.58% to +0.41%. Legacy
medians range -3.22% to +1.02%; all raw measurements are in the linked record. Post-exec sampled
VmHWM remains comparable for the existing paths.

New 128×96 tiled 9/7/ICT absolute medians, in ms per complete public API decode:

| Source | 12 bit | 16 bit |
| --- | --- | --- |
| Gray | 5.42 | 6.07 |
| RGB | 15.54 | 18.57 |
| Straight RGBA | 16.64 | 20.07 |

The new-path post-exec VmHWM samples range approximately 1.59–2.16 MiB. These
small inputs, single-host timings and sampled process peaks are not general
throughput or image-memory guarantees. Builds used two jobs; the sampled
cgroup peak across checks was about 3.99 GiB of 16 GiB, with zero OOM events.

## Reproduction and evidence

Run native tests with `cargo test -p wml2 --locked --release --no-default-features
--features jpeg2000,image-buffer-ex --lib --tests`. Add `high-bit-depth` for the
focused feature combination. Windows CI explicitly includes `jpeg2000_ex_97`
on i686; the Linux feature matrix discovers the new target normally.

Generate references with `generate_jpeg2000_ex_97.py --compress /path/opj_compress
--decompress /path/opj_decompress --work-dir .test-reference`. The binaries are
ordinary OpenJPEG 2.5.3 CLI tools; no codec repository is changed.

Actual WASM checks use `python3 -B wml2-test/scripts/verify_jpeg2000_ex_97_wasm.py
--overflow-checks --work-dir .test-wasm-97`, optionally `--default-features`.
Every temporary work directory must begin with `.test`. Builds use two jobs.

[Validation and hashes](jpeg2000-ex-97-validation.json),
[raw logs and measurement scripts](jpeg2000-ex-97-raw.json.gz) and
[source/reference/decoded display](jpeg2000-ex-97-display.png) record the final
checks and single-host performance observations. Measurements do not establish
universal throughput/RSS guarantees. Existing ignored/manual corpus checks and
optional absent external AVIS samples are not independent 9/7 validation.

JP2 method2 Gray/RGB ICC retention is now available without CMS application;
see [the ICC contract](jpeg2000-icc.md) for callback and owned-output identity.
