# WML2 0.0.43

## Changes
- Extend the bounded JPEG XL animation adapter to XYB RGB8/16 and SDR
  Gray8/16, optionally with one matching-depth, straight, full-resolution alpha
  channel. Published `jxl =0.8.0` continues to perform pixel reconstruction,
  layer coalescing, blending and orientation. Native and EX output preserves
  full-canvas RGBA16; ordinary callbacks round once to RGBA8.
- Preserve source and reconstruction/output ICC profiles separately. Expand
  simple Gray signalling to a matching neutral-axis RGB output profile without
  changing samples. Explicit sRGB APIs transform every frame from the actual
  output profile, leaving alpha unchanged. Arbitrary Gray reconstruction ICC
  expansion is refused rather than falsely labelling RGB output.
- Add `ImgError::kind()` and expose wrapped errors through `Error::source()`.
  Add Copy/Clone/equality/hash support to `ImgErrorKind`. Shared resource-limit
  checks retain their existing category and display text while attaching a
  typed `DecodeLimitExceeded` source with resource, requested and limit values.
- Add ordered warning access through `ImgWarnings::len`, `is_empty` and `iter`,
  plus `image_load_with_warnings` and `image_from_with_limits_and_warnings`.
  Existing convenience APIs and callbacks retain their signatures and warning
  behavior. Document codec-specific limitations in [diagnostics](../diagnostics.md).
- Update package and dependency examples to 0.0.43, reconcile both READMEs and
  current JPEG XL guides, and move the unreleased summary into these canonical
  notes. Release preparation changes no decoder/encoder implementation.

## Compatibility
- Default features, Rust 1.91 minimum version, all dependency versions and AVIF
  submodule pins are unchanged. JPEG XL remains opt-in and pure Rust; the
  parser-only `jxl =0.7.4` compatibility dependency remains separate from pixel
  decoding. There is no new codec fork, C/FFI backend, encoder or public policy API.
- Animation retains its existing input, canvas, layer, frame, metadata and
  workspace limits, exact timing requirements, cancellation and callback
  contracts. All decoding/CMS preparation completes before init/draw. Native
  timing retains rational ticks; common callbacks require exact integer
  milliseconds. Memory admission is not a total-heap or process-RSS guarantee.
- Animation previews/timecodes, HDR/float/tone mapping, unsupported depths,
  associated/subsampled/mixed-depth alpha, general extra channels and arbitrary
  Gray output ICC expansion remain unsupported. Tested SDR profiles do not
  establish general LUT, device-link, CMYK or unusual-profile conformance.
- Boxed errors are not newly required to be Send + Sync. No error-kind variant
  or warning trait requirement is added. Typed limit sources are not universal:
  codec-specific mapping/recovery can erase causes, and absence of a typed
  source does not prove actual out-of-memory. Callback Abort remains stop-success.
  Warnings are retained only on successful/recovered output, not fatal failures.
- Cargo treats 0.0.43 as a separate pre-1.0 compatibility interval from 0.0.42.
  Downstream consumers must select it explicitly. Viewer adoption is separate.

## Validation
- The merged implementation baseline
  [`865ea616a1f8085273bcce697f4032342e5145e1`](https://github.com/mith-mmk/wml2-on-rust/commit/865ea616a1f8085273bcce697f4032342e5145e1)
  passed [main checks](https://github.com/mith-mmk/wml2-on-rust/actions/runs/42449971857)
  and [bounded extended checks](https://github.com/mith-mmk/wml2-on-rust/actions/runs/42611471817).
- Historical independent all-frame libjxl references, native/EX precision,
  distinct-ICC conversion, Gray profile refusal, limits, truncation, cancellation
  and callback tests are recorded in [SDR validation](../jpeg-xl-sdr-validation.md)
  and [Gray validation](../jpeg-xl-gray-animation.md). The linked reports retain
  their source revisions, tolerances, fixture generators and benchmark limits.
- [Playback validation](../jpeg-xl-sdr-playback-validation.md) records execution
  of 13 test bodies in actual WASM under Node, all-frame Viewer-core comparisons,
  and eight fixtures played in an isolated Windows release Viewer. These are
  historical implementation checks, not a new downstream release or a browser
  native-JXL claim. Finite-loop GUI stopping and frame-pacing remain unverified.
- [Diagnostics validation](../diagnostics.md#validation-2026-11-08) records the
  feature matrix, callback/EXIF regressions, doc tests and paired JPEG benchmarks.
  Its passing counts and measured speed are specific to that revision/environment.
- The tag workflow runs full checks on the release commit and builds Linux,
  Windows and macOS example archives before creating the GitHub Release.
  Crates.io publication is a separate operation; neither a pushed tag nor an
  uploaded crate alone establishes that the release workflow completed.
